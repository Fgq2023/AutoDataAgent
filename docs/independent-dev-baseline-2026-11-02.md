# 独立开发子集：初步真实运行与失败分析

## 实验范围

2026-11-02，OpenCode Go / deepseek-v4.1-flash。
只运行 Bike Sharing 开发任务 I001–I003，每种条件一次；没有评估 Wine validation 或 Energy test。
这是开发冒烟测试，不是冻结模型/框架的正式泛化评测。

- NL-only：给模型自然语言目标和源数据概况；评分契约仅由外部评分器读取。
- contract-assisted：同样目标和数据，并向规划器/运行时验证器提供明确约束。
- 两种条件严格禁止 mock 回退，报告生成与目标表格都纳入完成判定。

原始运行记录保留，不覆盖、不重算成绩。

证据：`outputs/independent_eval_9h1g2qhz/` 与 `outputs/independent_eval_2put72xs/`。
每题均只发起一次模型调用，超时题也计为一次尝试，没有进入执行；没有选择性重跑并替换记录。
超时算端到端失败，但不是答案语义错误。新增评估字段将传输错误与规划、执行/验证和答案错误分开。

任务版本和框架同时变化，不能把两轮差异解释为框架修复导致的成功率提升。
样本太少且每题单次调用，不能据此断言显式约束更好或更差。
本轮没有观察到修订题上的模型代码修复调用，Python 修复能力由执行回归测试覆盖，
不宣称已由本轮真实开发任务证明其效果。

## 已落实的可靠性工作

- 分组错误反馈给出缺失与多余分组示例，而非只给相同组数。
- Python 参数修复保留输入引用与输出名称，检查语法后执行并验证；受同一恢复预算约束。
- 产物注册保存内容哈希快照，重试不能通过正常工具写入路径覆盖历史证据。
- 评估输出模型调用、错误接受数、失败阶段、任务/源数据/源码哈希和 Markdown 汇总。
- 本轮功能回归 86 项通过；六个原有场景和离线修复基准通过。
