# M4 implementation plan, 2026-11-05

Approved scope follows the project roadmap. Single-user localhost FastAPI with native HTML/JS and one active task.

1. Add RunService shared by CLI and Web. Build orchestrators from the same saved configuration. Persist job IDs, TaskSpec, clarification, run location and final status. Serialize work, support cooperative cancellation, reopen interrupted jobs and resume using M3 manifests.
2. Add FastAPI source listing, start/status/events/clarify/cancel/resume, safe artifact previews/download and consistent evidence ZIP export. Bind localhost and reject foreign origins. Artifact paths come from the run database and stay within that run.
3. Build a Chinese single page for goals, source selection, explicit mock/live and Docker/trusted-subprocess modes, clarification, run state, dependency/verification/recovery displays and artifact preview/export.
4. Add regression coverage for shared CLI behavior, clarification, single-run exclusion, cancellation, restart/recovery, artifact path bounds and ZIP contents. Install only the optional Web dependencies.
5. Prepare deterministic normal/recovery/resume demonstrations. Run the complete rehearsal twice through the HTTP endpoints and verify answers, charts, reports, traces and archives. Preserve the M2 eight-case matrix and M1 development baseline as linked midterm evidence.
6. Write launch instructions, architecture, limitations and rehearsal report. Record a candidate commit for the Dec 12 freeze. The calendar freeze and Dec 15 submission remain future human milestones.
7. Review, run full regression, and publish a reviewable M4 branch/PR with CI checks.

Key decisions. The task list is persisted locally to survive server restarts. Credentials remain process environment only. Cancellation occurs at execution boundaries and is bounded by existing call timeouts. A single server process is supported.
