## 状态与恢复

每次运行在 SQLite 保存有版本和校验摘要的清单，包含完整计划、计划修订、TaskSpec、配置、输入哈希、累计时间和模型请求数。模型端点、模型名、provider 和会话标识随运行保存，恢复时重建这些非敏感参数。API 密钥由当前进程环境提供。

步骤产物登记和成功检查点使用事务。请求、工具尝试和重规划在执行前登记。恢复会先核对全部输入及成功产物的哈希，再恢复状态。完成的步骤直接复用，未确定步骤的产物失效后重跑，已消耗预算继续计入。OS 文件锁防止并发恢复。模型传输错误最多重试一次，每个实际 HTTP 请求分别扣减预算。请求与 Python 执行超时受剩余运行时间限制。

恢复命令为 python -m agent --resume <运行目录>。保存为 LLM 模式的运行需要当前环境提供有效凭据。旧版运行缺少清单时明确拒绝恢复，原有查看、导出接口继续可用。

## Docker

构建命令为 docker build -f docker/Dockerfile.sandbox -t autodataagent-sandbox:local 。

CLI 显式选择 --sandbox-backend docker。独立任务评测脚本默认使用 Docker，并在镜像或引擎不可用时停止。可信本地演示可显式使用 subprocess。

Docker 只接收一份只读输入和独立输出目录。网络、写入根文件系统、权限提升及额外 capabilities 受限。内存上限为 512 MiB、CPU 为一核、进程上限为 64。容器内独立计时器在宿主进程被终止后仍限制执行时间。Docker 错误不会触发后端切换。

## 实测证据

真实容器验收脚本为 scripts/verify_m3.py，结果保存在 outputs/m3_acceptance_rqfjzaln/results.json。四组均通过：

- 输入和根文件系统只读、评分文件不可见、网络与凭据隔离，cgroup 资源限制。
- Python 超时后容器清理。
- 在观察到运行中的容器后强制终止宿主进程，容器仍会在独立截止时间内退出。
- CSV、SQLite、Markdown 联合任务通过容器内 Python 汇总，独立核对 East=85、West=70，报告引用政策行，完成后恢复成功。

离线恢复测试包含真实子进程 os._exit 中断。恢复复用两个上游步骤，未确定步骤重新执行且前次尝试继续计费。还覆盖输入/产物/清单被修改、并发恢复、工具/模型/时间预算耗尽、保存模型模式及端点/会话恢复。

## 适用边界

初始规划完成后才有可恢复计划。规划过程中终止需要重新发起任务。非正常退出后，从最后持久化记录至恢复的间隔保守计入累计时间，包含停机时间。

容器后端隔离生成的 Python 代码。文件读取、SQL、连接、绘图等受控内置工具仍在宿主执行。当前验收采用合成固定任务，模型规划链路已在 M2 验证。容器隔离验证衡量已配置限制，不能据此声称可防御所有宿主内核或 Docker 漏洞。

最终离线全套 121 项通过，6 个基线场景通过。模型身份恢复的最后调整另经 14 项定向回归及四组真实 Docker 验收复核。


## M3 缺口补齐

普通 CLI 的 LLM 规划入口现在直接传播模型和计划错误。401/403 认证错误、402 额度错误、429 额度或限流错误会停止整个运行，修复器也会传播停止信号。离线演示显式选择 mock。

运行会在初始规划前建立 SQLite 清单。每个实际请求记录开始、成功或失败，传输重试记录原因、等待时间和下一次尝试。初始规划失败的轨迹和预算也会保存；CLI 输出对应运行目录。规划未完成的运行保留为 planning_failed，恢复入口要求检查轨迹并重新发起任务。

本轮全套 131 项测试通过，另新增的 CLI 错误输出与轨迹位置用例在 7 项定向测试中通过。6 个基线场景、4 组真实 Docker 验收通过。最新容器证据位于 outputs/m3_acceptance_ucjtvrke/results.json。
